# Недельный обзор

Собери обзор из доступной недели и честно обозначь покрытие. Это не отчёт о
продуктивности и не повод придумывать события за отсутствующие дни.

## Собери неделю

1. Через `glob` с `cwd="$VAULT"` найди 7 available daily summaries с самыми
   поздними датами в `summaries/daily/*.md` и прочитай их через `read_file`.
2. Если доступно 1–2 саммари, назови результат лёгким срезом. Если нет ни
   одного, сообщи, что недельный обзор по дням собрать нельзя, и не изображай
   полную неделю.
3. Вызови `tasks` с `action="list"`, чтобы найти просроченные и открытые задачи.
4. Выполни ограниченный `memory_search` по решениям, обязательствам и блокерам,
   которые встречаются в саммари. Открывай только карточки, необходимые для
   проверки конкретного пункта; не обходи весь vault.

## Проследи изменения

Для каждого существенного решения укажи одну метку:

- `STABLE` — подтверждено и не менялось;
- `NEW` — появилось в доступной неделе;
- `CONFLICTING` — актуальные источники расходятся;
- `CHANGED` — более поздний датированный источник явно заменил прежний.

Верх карточки и frontmatter — текущая правда. History и `status: superseded`
показывают прошлое, но не текущий факт. При конфликте приведи обе версии, даты
и источники; не разрешай его молча. `INFERRED` помечай как предположение,
`AMBIGUOUS` — как неопределённость.

## Ответ

Используй четыре раздела:

1. **Покрытие** — какие даты и сколько саммари реально прочитано.
2. **Темы и прогресс** — повторяющиеся темы, завершённое и подтверждённые
   изменения.
3. **Решения, обязательства и блокеры** — сначала `CONFLICTING`, затем
   просроченное, открытые обязательства и только потом остальные темы.
4. **Следующая неделя** — ровно 3 next-week priorities либо меньше, если
   подтверждённых оснований не хватает. Не дополняй список общими советами.

For every memory-derived claim, включая каждый тезис и приоритет, добавляй
`[Источник: <vault-relative path>]`; для конфликтов указывай оба пути. Если в
источнике есть `telegram:message:<chat>:<message>`, сохрани этот идентификатор
рядом с путём. Задачи обозначай их ID. Если источник недоступен, назови пробел и
ограничь выводы.

This workflow is read-only: do not create, modify, or send tasks, cards, files,
messages, calendar events, or other external actions.
